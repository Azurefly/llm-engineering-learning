# V3: Timed Exams and Coding Labs

V3 extends the randomized exam system with two major capabilities:

1. **server-enforced exam deadlines with autosave**;
2. **Docker-isolated coding questions graded by pytest**.

## Timed exams

Default durations:

- weekly exam: 30 minutes;
- stage exam: 50 minutes;
- mistake review: 20 minutes.

They can be configured with:

```bash
LLM_EXAM_WEEKLY_MINUTES=30
LLM_EXAM_STAGE_MINUTES=50
LLM_EXAM_MISTAKE_MINUTES=20
```

The deadline is persisted in SQLite (`exam_runtime`). The browser countdown is only a display; the server is the source of truth.

Answers are autosaved on changes, periodically saved every 10 seconds, restored after refresh, and automatically submitted from the last saved draft when the deadline expires.

## Coding labs

Current system-graded coding labs:

- Week 2: Stable Softmax;
- Week 8: RAG Top-K retrieval;
- Week 11: Agent loop stop guard;
- Week 18: Coding Agent state decision.

Open:

```text
http://127.0.0.1:8765/coding-labs
```

Scores are based on pytest test pass rate and stored in `code_attempts`.

## Safe default

Code execution is disabled unless explicitly enabled:

```text
LLM_CODE_RUNNER=disabled
```

## Enable the Docker sandbox

Build the sandbox image:

```bash
docker build -t llm-learning-sandbox:py312 sandbox
```

Run the learning app from the host Python environment with Docker access:

```bash
export LLM_CODE_RUNNER=docker
export LLM_CODE_RUNNER_IMAGE=llm-learning-sandbox:py312
python run.py
```

On Windows PowerShell:

```powershell
$env:LLM_CODE_RUNNER="docker"
$env:LLM_CODE_RUNNER_IMAGE="llm-learning-sandbox:py312"
python run.py
```

The application process must be able to invoke the local Docker CLI.

The default Docker Compose setup intentionally does **not** mount the Docker socket. Exposing `/var/run/docker.sock` to the web application container would effectively grant host-level privileges. A future containerized deployment should use a separate restricted runner service instead.

## Sandbox controls

Each coding submission runs in a disposable container with controls including:

```text
--network none
--memory 128m
--cpus 0.50
--pids-limit 64
--read-only
--cap-drop ALL
--security-opt no-new-privileges
restricted tmpfs for /tmp
read-only /workspace mount
```

This is designed for a trusted personal workstation, not as a public multi-tenant online judge.

## Data and backup

V3 adds:

- `exam_runtime`: deadlines, duration, autosave draft, last-save time, auto-submit flag;
- `code_attempts`: learner source, pytest output, passed/total tests, score, result metadata.

`/backup.json` includes both tables.

## CI

GitHub Actions now has two jobs:

1. `test`: full pytest suite with code execution disabled;
2. `sandbox-smoke`: builds the sandbox image and actually runs a controlled coding submission through the Docker grading path.
