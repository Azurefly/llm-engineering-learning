# V3：计时考试与代码实训

V3 在 V2 随机组卷、错题本、阶段考试和成绩趋势基础上增加两类能力：

1. **服务端计时考试 + 自动保存**；
2. **Docker 隔离代码题 + pytest 自动评分**。

## 1. 计时考试

不同考试默认时长：

- 周测：30 分钟；
- 阶段考试：50 分钟；
- 错题专项：20 分钟。

可通过环境变量调整：

```bash
LLM_EXAM_WEEKLY_MINUTES=30
LLM_EXAM_STAGE_MINUTES=50
LLM_EXAM_MISTAKE_MINUTES=20
```

系统将截止时间写入 SQLite 的 `exam_runtime` 表。浏览器中的倒计时只负责展示，真正的截止判断在服务端。

答题过程中：

- 输入变化后自动保存；
- 每 10 秒进行一次兜底保存；
- 刷新页面后恢复最后一次保存的答案；
- 超时后系统按最后保存的草稿自动交卷；
- 已提交的 Attempt 不能再次修改。

## 2. 代码实训

当前提供 4 个系统评分代码题：

- Week 2：稳定 Softmax；
- Week 8：RAG Top-K 检索；
- Week 11：Agent Loop 停止条件；
- Week 18：Coding Agent 状态决策。

入口：

```text
http://127.0.0.1:8765/coding-labs
```

代码题通过 pytest 测试用例数量计算成绩，并保存到 `code_attempts`。

## 3. 安全默认值

代码执行默认关闭：

```text
LLM_CODE_RUNNER=disabled
```

因此普通 `python run.py` 或 Docker Compose 启动时，不会直接执行学习者提交的任意代码。

## 4. 启用 Docker Sandbox

推荐仅在可信的个人开发机上启用。

先构建沙箱镜像：

```bash
docker build -t llm-learning-sandbox:py312 sandbox
```

然后以 Python 主程序方式启动学习应用：

### Windows PowerShell

```powershell
$env:LLM_CODE_RUNNER="docker"
$env:LLM_CODE_RUNNER_IMAGE="llm-learning-sandbox:py312"
python run.py
```

### Linux / macOS

```bash
export LLM_CODE_RUNNER=docker
export LLM_CODE_RUNNER_IMAGE=llm-learning-sandbox:py312
python run.py
```

应用进程需要能够调用本机 Docker CLI。

> 当前默认 Docker Compose **不会挂载 Docker Socket**。这是刻意的安全设计，因为把 `/var/run/docker.sock` 暴露给 Web 应用容器基本等同于授予宿主机高权限。若未来需要“应用本身也容器化 + 代码沙箱”，建议增加独立受限 Runner 服务，而不是直接把 Docker Socket 暴露给主应用。

## 5. 沙箱限制

每次代码题运行使用一次性 Docker 容器，默认限制包括：

```text
--network none
--memory 128m
--cpus 0.50
--pids-limit 64
--read-only
--cap-drop ALL
--security-opt no-new-privileges
/tmp 使用受限 tmpfs
/workspace 只读挂载
```

测试镜像预装 pytest，执行结束后容器自动删除。

该方案适用于个人本地学习，不应直接视为面向不受信任公网用户的多租户代码判题平台。

## 6. 数据与备份

V3 新增：

- `exam_runtime`：时长、截止时间、自动保存草稿、最后保存时间、是否自动交卷；
- `code_attempts`：代码、pytest 结果、测试通过数、系统分数和运行信息。

`/backup.json` 已包含上述数据。

## 7. 自动测试

仓库 GitHub Actions 包含两个 Job：

1. `test`：运行完整 pytest，代码执行器保持 disabled；
2. `sandbox-smoke`：真实构建沙箱镜像，并执行一个受控代码题，验证 Docker 隔离执行和自动评分链路。
