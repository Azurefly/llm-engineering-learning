# V5：逐题自适应测试与本地长期运行

V5 的目标不是继续增加后台页面，而是让项目具备可长期使用的学习、考试、数据保护和自检闭环。

## 1. 稳定启动入口

应用现在统一从：

```text
app.current:app
```

启动。`main_v2.py`、`main_v3.py`、`main_v4.py`、`main_v5.py` 作为历史兼容层保留，日常启动和自动测试不再直接依赖版本文件。

```bash
python run.py
```

或：

```bash
docker compose up -d --build
```

访问 `http://127.0.0.1:8765`。

## 2. 逐题自适应测试（CAT）

入口：`/adaptive-test`

与 V4 的“按薄弱项生成一整张复习卷”不同，V5 每答完一题才决定下一题。

选题综合考虑：

- 当前知识点掌握度；
- 本次会话刚刚得到的成绩；
- Easy / Medium / Hard 难度；
- 题目历史曝光次数；
- 目标知识点覆盖情况。

基本策略：

```text
掌握度 < 45   → Easy 优先
45 ～ 74      → Medium 优先
>= 75         → Hard 优先
```

历史出现次数越多的题，下一次被选中的权重越低。

默认每次 12 题，可配置：

```text
LLM_ADAPTIVE_MAX_ITEMS=12
```

允许范围为 6～30。

进行中的自适应测试会保存在 SQLite 中，可以关闭页面后回来继续，也可以主动放弃。

## 3. 题目不可变快照

随机考试和自适应测试都会保存当次试题的完整快照，包括：

- 中文题干；
- 英文题干；
- 题型；
- 分值；
- 选项；
- 标准答案；
- 填空允许答案；
- 简答题 Rubric。

因此未来修改题库后，历史成绩单仍然使用考试当时的题目，不会被新版本题库重新解释。

## 4. 题库扩展与质量门禁

V5 为 Week 0～18 每周增加了工程应用题：

- 工程场景单选；
- 排障/治理多选；
- 设计型简答题。

目前题库达到约 190+ 题，并在 CI 中执行自动质量检查：

- Question ID 唯一；
- 中英文题干完整；
- 选项值无重复；
- 标准答案必须存在于选项；
- 填空题必须存在 accepted answers；
- 简答题必须有多个 Rubric 概念点；
- 每周最低题量；
- 难度覆盖检查。

## 5. 全局搜索

入口：`/search`

统一搜索：

- 课程 Markdown；
- 个人思考；
- 标签；
- 外部资料标题、说明与 URL。

所有结果可以直接跳回课程、思考编辑页或资料编辑页。

## 6. 数据备份与恢复

入口：`/data-management`

支持：

- 下载完整 JSON 备份；
- 校验备份格式；
- 从备份恢复；
- 恢复前自动生成安全快照；
- 兼容旧版备份结构；
- 未知数据表拒绝导入；
- 事务恢复，失败自动回滚。

所有 `data/*` 文件均被 `.gitignore` 排除，避免本地学习记录、思考、链接、成绩和备份误提交到 GitHub。

### 自动备份

应用启动时默认检查滚动备份：

```text
LLM_AUTO_BACKUP=1
LLM_AUTO_BACKUP_HOURS=24
LLM_AUTO_BACKUP_KEEP=10
```

只有已有学习数据时才会生成备份。

## 7. SQLite 长期运行设置

本地数据库启用：

```text
journal_mode = WAL
busy_timeout = 5000 ms
foreign_keys = ON
synchronous = NORMAL
```

用于减少考试自动保存、笔记、代码成绩同时写入时出现 `database is locked` 的概率。

## 8. 系统诊断

入口：`/diagnostics`

机器可读接口：`/api/diagnostics`

检查：

- SQLite integrity check；
- WAL / busy timeout；
- 数据库大小和表数量；
- 题库质量门禁；
- 题目总量；
- Docker Code Runner 是否启用；
- 沙箱镜像名称；
- 本地安全快照状态。

## 9. 本地 Web 安全边界

默认启动仍只面向本机。

V5 额外增加：

- Trusted Host；
- 跨站写请求拦截；
- `X-Content-Type-Options: nosniff`；
- `X-Frame-Options: DENY`；
- `Referrer-Policy`；
- `Permissions-Policy`；
- 敏感 JSON `Cache-Control: no-store`。

默认 Allowed Hosts：

```text
127.0.0.1
localhost
[::1]
```

需要自行暴露到其他主机名时，可配置：

```text
LLM_ALLOWED_HOSTS=learning.local,192.168.1.10
```

若开放到局域网/公网，仍建议在前方增加认证反向代理；本项目默认定位为单用户本地工具。

## 10. Docker 加固

Compose 默认：

- 只映射 `127.0.0.1:8765`；
- read-only root filesystem；
- `/tmp` 使用受限 tmpfs；
- drop all Linux capabilities；
- `no-new-privileges`；
- 内置应用健康检查。

## 11. 可复现依赖

开发时可参考宽范围：

```text
requirements.txt
requirements-dev.txt
```

Docker 和 CI 使用已验证锁定组合：

```text
requirements.lock.txt
requirements-dev.lock.txt
```

Dependabot 每月检查 Python 与 GitHub Actions 更新。

## 12. CI 验收

GitHub Actions 分为：

1. `test`：完整 pytest；
2. `sandbox-smoke`：真实构建代码沙箱并执行 pytest 自动评分；
3. `app-docker-smoke`：真实启动加固后的 Docker Compose，然后验证当前主要页面、搜索和诊断接口。

这三层分别覆盖业务逻辑、学习者代码隔离、最终部署形态。
