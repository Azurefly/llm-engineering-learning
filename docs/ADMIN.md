# 超级管理员与用户管理

多用户版本提供 `superadmin` 与普通 `user` 两种账号角色。超级管理员负责**账号管理**，不会因此获得读取其他用户学习数据库的权限。

## 超级管理员产生规则

- 全新安装：第一个成功注册的账号自动成为 `superadmin`。
- 已有多用户数据升级：如果账号库中还没有超级管理员，系统自动把最早注册的现有账号升级为 `superadmin`。
- 后续超级管理员可以在“用户管理”中把其他用户提升为 `superadmin`。
- 系统始终要求至少保留一个启用状态的超级管理员；超级管理员不能在管理页停用或降低自己的角色。

## 用户管理入口

登录超级管理员账号后打开：

```text
/admin/users
```

侧边栏也会显示“用户管理 / ADMIN”。普通用户访问该地址返回 `403`。

## 可以管理的内容

超级管理员可以：

- 查看用户名、显示名称、角色、注册时间、最近登录时间、账号状态和有效 Session 数量；
- 创建新账号，即使 `LLM_ALLOW_REGISTRATION=0` 已关闭自主注册；
- 修改用户的用户名和显示名称；
- 启用或停用账号；
- 将普通用户提升为超级管理员，或在安全条件满足时降级其他超级管理员；
- 为其他用户重置密码；
- 重置密码时立即注销该用户全部旧 Session。

为了保护学习数据，管理页当前不提供“硬删除用户”操作。离职、停用或不再使用的账号应优先使用“停用账号”，对应用户数据库和备份仍会保留。

## 用户自己修改密码

所有用户均可进入：

```text
/account
```

修改自己的用户名、显示名称和密码。修改密码需要输入当前密码；成功后该账号的全部 Session 会立即失效，并要求使用新密码重新登录。

## 数据隔离边界

超级管理员管理的是全局账号库：

```text
data/accounts.db
```

用户学习数据继续物理隔离：

```text
data/users/<storage-key>/learning.db
```

超级管理员页面不会打开、合并或展示其他用户的：

- 学习进度；
- 考试和答案；
- 错题；
- 代码实训；
- 思考笔记；
- 外部链接；
- 自适应能力画像；
- 用户个人备份。

## 注册控制

自主注册仍由环境变量控制：

```text
LLM_ALLOW_REGISTRATION=1
```

关闭：

```text
LLM_ALLOW_REGISTRATION=0
```

关闭后，公开注册页不可用，但超级管理员仍可以从“用户管理”创建账号。

## 安全行为

- 密码使用带随机 Salt 的 PBKDF2-HMAC-SHA256 保存，不保存明文密码。
- Session Cookie 为 HttpOnly。
- 数据库只保存 Session Token 的 SHA-256 摘要。
- 管理员重置密码、停用账号都会撤销目标用户现有 Session。
- 普通用户不能调用超级管理员路由。
- CI 同时验证 Python 权限测试和真实 Docker 中的管理员/普通用户访问边界。
