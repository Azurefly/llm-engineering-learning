# V5: Sequential Adaptive Testing & Long-Term Local Operation

V5 focuses on making the project reliable for long-term daily learning rather than adding more generic management screens.

## 1. Stable entrypoint

The supported runtime entrypoint is:

```text
app.current:app
```

Versioned `main_v*.py` modules remain compatibility entrypoints only. The supported runtime explicitly composes feature routers instead of chaining historical version modules.

Start with:

```bash
python run.py
```

or:

```bash
docker compose up -d --build
```

Open `http://127.0.0.1:8765`.

## 2. Sequential adaptive testing (CAT)

Entry: `/adaptive-test`

Unlike V4 adaptive review, V5 chooses the next item only after the previous answer is graded.

Selection considers:

- current knowledge mastery;
- results from the current session;
- Easy / Medium / Hard difficulty;
- historical question exposure;
- target-knowledge coverage.

Default difficulty policy:

```text
mastery < 45   -> Easy preferred
45-74          -> Medium preferred
>= 75          -> Hard preferred
```

Frequently exposed items are automatically down-weighted. Once a CAT session is materialized as a formal exam result, that materialized row is excluded from exposure counts so the same answer is not counted twice.

Default length is 12 items and can be configured with:

```text
LLM_ADAPTIVE_MAX_ITEMS=12
```

Allowed range: 6-30.

Active sessions persist in SQLite and can be resumed or abandoned.

## 3. Immutable question snapshots

Every generated exam freezes the complete item definition used at that moment, including bilingual prompts, options, answers, accepted fill answers, points, types, and short-answer rubrics.

Adaptive sessions freeze each item as soon as it is selected, so even an interrupted session resumes against the same question content. Historical result pages therefore remain reproducible after the live question bank changes.

## 4. Expanded question bank and quality gate

Week 0-18 each receive additional engineering-oriented items:

- scenario single-choice;
- diagnostic/governance multiple-choice;
- design-oriented short answers.

The bank is roughly 190+ items. CI validates unique IDs, bilingual prompts, answer/option integrity, fill accepted answers, short-answer rubrics, minimum per-week volume, and difficulty coverage.

Short-answer Latin technical terms use token-boundary matching so acronyms such as `RAG`, `MCP`, and `SFT` cannot receive credit merely because they appear inside unrelated words. Chinese rubric phrases continue to use natural substring matching.

## 5. Global search

Entry: `/search`

Searches course Markdown, personal thoughts, tags, saved resource titles/descriptions, and URLs from one place.

## 6. Backup and restore

Entry: `/data-management`

Supports full JSON export, validated restore, explicit destructive-replace confirmation, pre-restore safety snapshots, legacy backup compatibility, table allow-listing, HTTP(S)-only restored resource URLs, bounds checks for key fields, and transactional rollback on failure.

In Python mode all files under `data/` are ignored by Git except `.gitkeep`, preventing local learning history or backups from being committed accidentally.

### Rolling automatic backup

On startup the application can create periodic local backups:

```text
LLM_AUTO_BACKUP=1
LLM_AUTO_BACKUP_HOURS=24
LLM_AUTO_BACKUP_KEEP=10
```

No backup is created for an empty learning database.

## 7. SQLite reliability

The local database uses WAL, a 5-second busy timeout, foreign keys, and NORMAL synchronous mode to reduce lock contention from autosave, notes, results, and coding-lab writes.

## 8. Diagnostics

Entry: `/diagnostics`

Machine-readable endpoint: `/api/diagnostics`

Checks SQLite integrity and settings, database size, question-bank quality, bank volume, coding-runner configuration, sandbox image, and local safety snapshots.

## 9. Local web hardening

V5 adds Trusted Host enforcement, cross-site write protection, anti-framing and MIME-sniffing headers, restrictive browser permissions, referrer policy, and no-store caching for sensitive JSON endpoints.

Default hosts are local-only. Additional hostnames can be configured with:

```text
LLM_ALLOWED_HOSTS=learning.local,192.168.1.10
```

If exposing the app to a LAN or the public internet, place authentication and a reverse proxy in front of it; the default product scope remains a single-user local tool.

## 10. Hardened Docker Compose and persistence

The default Compose service:

- binds only to `127.0.0.1:8765`;
- persists `/data` in the Docker-managed named volume `llm-engineering-learning-data`;
- uses a restricted `/tmp` tmpfs;
- drops all Linux capabilities;
- enables `no-new-privileges`;
- includes an application healthcheck.

The default no longer bind-mounts host `./data`. After `cap_drop: ALL`, the container root user no longer has `DAC_OVERRIDE`; on Linux, a host-owned bind directory can therefore prevent SQLite from creating `/data/learning.db`. A Docker-managed named volume avoids that cross-platform UID/permission problem without restoring the capability.

```text
docker compose down
```

preserves learning data. Only:

```text
docker compose down -v
```

explicitly deletes the named volume. Prefer the in-app JSON export/restore workflow for data migration.

## 11. Verified dependency pins

Flexible dependency specifications remain in `requirements.txt` and `requirements-dev.txt`. Docker and CI use verified direct dependency pins from `requirements.lock.txt` and `requirements-dev.lock.txt`.

Dependabot checks Python and GitHub Actions updates monthly; every update must still pass the complete CI workflow.

## 12. CI acceptance

GitHub Actions validates:

1. full pytest on Ubuntu Python 3.11, Ubuntu Python 3.12, and Windows Python 3.12;
2. `sandbox-smoke`, which builds the real learner-code sandbox and verifies pytest grading;
3. `app-docker-smoke`, which starts Docker Compose and checks the current dashboard, adaptive learning, CAT, search, diagnostics, and health endpoint.

Together they validate application behavior, cross-platform Python execution, untrusted-code isolation, and the final deployment form.
